# Snapbuild — тестовое задание

Локальная компонентная реконструкция продуктового лендинга
[snapbuild.ru](https://snapbuild.ru/). Текущая версия воспроизводит оригинальные секции,
адаптивность и основные интерактивные состояния. Следующий этап — разработка и интеграция пяти
новых секций.

## Локальный запуск

```bash
yarn install
yarn dev
```

Production-сборка и полная проверка:

```bash
yarn build
yarn check
```

## Стек

- React 19;
- Vite;
- TypeScript strict;
- Yarn;
- shadcn/ui и Radix UI;
- Tailwind CSS 4;
- CSS Modules;
- Vitest и Testing Library.

## Воспроизведённые части оригинала

- фиксированная полупрозрачная шапка и мобильное меню;
- первый экран с фирменным градиентом и интерфейсом продукта;
- логотипы клиентов;
- продуктовые карточки;
- интерактивные форматы материалов;
- сравнительная таблица;
- блок безопасности;
- горизонтальный roadmap;
- FAQ;
- финальный CTA;
- подвал.

## Анализ стилистики

Для реконструкции были сопоставлены desktop, tablet и mobile версии оригинального сайта.
Зафиксированы TT Commons Pro, светло-серый фон, крупная типографика, свободная сетка,
минимальные рамки, чёрные активные состояния, мягкий фирменный градиент и плавные появления
контента. Публичные изображения исходного лендинга сохранены локально, чтобы страница не
зависела от внешнего CDN.

## Дизайн-система и план новых секций

- [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) - токены, типографика, сетка, радиусы, состояния,
  motion и архитектурные правила baseline;

## Архитектура

Компоненты строятся по последовательности:

```text
shadcn primitive -> brand primitive -> entity -> feature -> widget -> page
```

Полные правила именования, декомпозиции и работы со стилями находятся в
[CODE_STYLE.md](./CODE_STYLE.md).

## Публикация

Vite настроен на относительный base path для дальнейшей публикации на GitHub Pages. Ссылка на
опубликованную версию будет добавлена после создания репозитория и настройки workflow.

## AI-инструменты

Codex использовался для анализа PDF и исходного интерфейса, декомпозиции компонентов,
реализации, адаптивной проверки и технического QA. Все решения и сгенерированный код проходят
проверки TypeScript, ESLint, Vitest и production build.
