# Дизайн-система baseline Snapbuild

## 1. Назначение

Этот документ описывает наблюдаемую дизайн-систему оригинального лендинга Snapbuild и её
локальную реализацию. Это не попытка восстановить внутренний source code оригинала. Это
зафиксированный набор правил, по которым новые секции должны выглядеть естественным
продолжением уже воспроизведённой страницы.

Baseline зафиксирован тегом `baseline-original-copy`.

Главный принцип: новая секция может быть сложнее по структуре, но не должна вводить новый
визуальный язык. Она использует те же поверхность, типографику, ритм, радиусы, градиенты,
состояния и motion-паттерны.

## 2. Визуальная идея

Snapbuild выглядит как спокойный светлый продуктовый лендинг с очень крупной типографикой и
редкими, но заметными акцентами:

- светло-серый холст страницы;
- белые поверхности и карточки без тяжёлых рамок;
- чёрный текст и чёрные primary controls;
- мягкий брендовый градиент от тёплого оранжевого через розовый к фиолетово-голубому;
- много свободного пространства вокруг контента;
- интерфейсные изображения сдержанной геометрии и большими скруглениями;
- горизонтальные композиции, которые на мобильном становятся вертикальными или сохраняют
  собственный горизонтальный scroll-контейнер;
- motion как часть композиции: появление, stagger, прогресс, раскрытие и drag.

Не используем без специального обоснования: тёмные панели, glassmorphism с сильным blur,
многоцветные карточки, декоративные иконки ради заполнения пустоты, случайные тени и
градиенты, не связанные с брендом.

## 3. Технологический слой

### 3.1. Источники стилей

1. Глобальные CSS-токены в `src/app/styles/index.css`.
2. CSS Modules конкретного компонента.
3. Tailwind/shadcn-варианты для базовых интерактивных примитивов.
4. Данные секции и компонентные варианты.

Один параметр не должен иметь несколько независимых источников истины. Если значение
повторяется в двух или более секциях, сначала проверяем, не является ли оно токеном.

### 3.2. Базовые токены

| Роль                 | Токен                  | Значение baseline        |
| -------------------- | ---------------------- | ------------------------ |
| Фон страницы         | `--background`         | `#f5f5f6`                |
| Основной текст       | `--foreground`         | `#000000`                |
| Белая поверхность    | `--card` / `--popover` | `#ffffff`                |
| Приглушённый текст   | `--muted-foreground`   | `#5a5b62`                |
| Тонкая граница       | `--border`             | `#e6e6e7`                |
| Мягкий muted surface | `--muted`              | `#eeeeef`                |
| Primary control      | `--primary`            | `#000000`                |
| Текст на primary     | `--primary-foreground` | `#ffffff`                |
| Вторичная surface    | `--secondary`          | `#ffffff`                |
| Брендовый акцент     | `--accent`             | `#ffb8cf`                |
| Focus ring           | `--ring`               | `#000000`                |
| Межсекционный ритм   | `--section-gap`        | `clamp(3rem, 4vw, 5rem)` |

Основной брендовый градиент: `--gradient-brand` в `index.css`.

Для нового декоративного градиента сначала проверяем, можно ли использовать существующий
`--gradient-brand`. Новый градиент допустим только если он является отдельным осмысленным
состоянием, а не локальной попыткой подобрать другой розовый.

### 3.3. Типографика

Используется локальный `TT Commons Pro` из `public/assets/fonts/fonts.css`.

Поддерживаемые начертания:

- `400` - обычный текст;
- `500` - основной UI, подписи, описания и заголовки секций;
- `600` - hero, CTA и акцентные заголовки.

Базовые правила:

- `body`: 16px, `font-weight: 400`, `line-height: 1.5`;
- основной заголовок секции: 52px на desktop, 32px на mobile;
- hero title: крупнее заголовка секции, с плотным `line-height`;
- body copy: 16px desktop/tablet, 14px mobile;
- card title: 16-20px в зависимости от роли;
- muted copy всегда использует `--muted-foreground`, а не случайный серый;
- крупные заголовки используют отрицательный `letter-spacing`, но он задаётся в контексте
  компонента, а не глобально для всего текста.

Текст не растягиваем принудительно через `letter-spacing`, если проблема вызвана неверным
шрифтом, шириной контейнера или line-height. Сначала проверяем font family, размер и ширину
колонки.

### 3.4. Сетка и брейкпоинты

| Режим   |     Ширина |  Базовый gutter | Поведение                                      |
| ------- | ---------: | --------------: | ---------------------------------------------- |
| Mobile  |   до 767px |            16px | вертикальные композиции, крупные touch targets |
| Tablet  | 768-1023px |            20px | промежуточная fluid-сетка, часто одна колонка  |
| Desktop |  от 1024px | `--page-gutter` | широкая композиция и многоколоночные блоки     |

Для pixel-perfect размеров baseline используются reference widths:

- mobile: `3.75` для расчётов `calc(value / 3.75 * 1vw)`;
- tablet: `8.1`;
- desktop: `14.4` до 2560px.

Эти коэффициенты применяются только там, где этого требует визуальный референс. Для нового
обычного layout предпочтительнее существующие токены, `clamp()` и CSS Grid.

Стандартный section contract:

- внешний горизонтальный gutter задаёт widget;
- внешний vertical rhythm задаёт `main` как `flex-column` с единым `gap: var(--section-gap)`;
- hero и logo marquee объединены в intro-группу без искусственного gap между ними;
- секция не использует вертикальный padding для компенсации соседнего блока;
- внутренний `gap` принадлежит widget;
- не добавляем margin к entity, чтобы компенсировать неправильный layout родителя.

### 3.5. Радиусы

| Роль           | Токен                   | Desktop | Mobile |
| -------------- | ----------------------- | ------: | -----: |
| Control        | `--radius-control`      |    12px |   12px |
| Header         | `--radius-header`       |    16px |   16px |
| Content card   | `--radius-content-card` |    20px |   20px |
| Hero media     | `--radius-hero-shot`    |    16px |    6px |
| Use case media | `--radius-use-media`    |    12px |    6px |
| CTA shell      | `--radius-cta-shell`    |    16px |   32px |
| Comparison     | `--radius-comparison`   |    20px |   20px |

Радиус выбирается по роли элемента, а не по месту на странице. Кнопка не получает радиус
карточки только потому, что находится внутри карточки.

### 3.6. Тени и поверхности

- Базовая карточка: белый фон, без тяжёлой тени.
- Header: полупрозрачный белый фон, blur и очень мягкая тень только в scrolled-state.
- Menu: белая полноэкранная поверхность на mobile.
- CTA shell: белая основа с брендовой градиентной заливкой и мягкими декоративными blobs.
- Popup/cookie: белая поверхность с аккуратной тенью, без цветной рамки.

Если новой секции нужна иерархия, сначала используем контраст поверхности, отступ и
типографику. Тень является последним, а не первым способом разделить блоки.

## 4. Повторяемые UI-паттерны

### 4.1. Section heading

`SectionHeading` - основной контракт для заголовка секции:

- заголовок слева на desktop;
- description под заголовком или в правой части, если это позволяет композиция;
- одна и та же типографическая шкала;
- description muted;
- локальная настройка ширины допустима только для конкретной композиции.

Новая секция не создаёт собственную параллельную систему заголовков без визуальной причины.

### 4.2. Card

Карточка должна иметь ясную роль:

- media card - изображение, title, description;
- data card - число/метрика, label, пояснение;
- quote card - цитата, автор, компания, результат;
- action card - задача, поля или CTA.

У карточки должны быть предсказуемые состояния `default`, `hover`, `focus-visible`, а для
интерактивной карточки также `active` и `pressed`.

### 4.3. Buttons

- primary: чёрный фон, белый текст;
- secondary: белый фон, брендовый градиентный текст;
- текст CTA не заменяется plain black/white, если в референсе используется gradient label;
- hover для чёрных CTA не должен самовольно затемнять кнопку;
- shine проходит слева направо по тексту при hover/focus-visible;
- touch target не меньше 44px, если это не точная копия существующего control;
- `cursor: pointer`, `disabled`, `focus-visible` и `prefers-reduced-motion` обязательны.

### 4.4. Tabs и accordion

Tabs используют чёрный active-state, спокойные inactive-state и не меняют порядок контента
на mobile, если оригинальный паттерн этого не делает.

Accordion:

- controlled или Radix state;
- `aria-expanded` и `aria-controls`;
- раскрытие через реальную высоту/состояние контента, а не через резкое появление;
- сохраняет высоту соседних элементов без скачков;
- клавиатура и reduced motion обязательны.

### 4.5. Горизонтальные треки

Roadmap и потенциальные case-study/integration rails используют отдельный scroll viewport:

- page-level horizontal overflow запрещён;
- drag/swipe работает только внутри viewport;
- scrollbar скрыт визуально, но scroll остаётся доступным;
- на desktop track может быть статичным, на mobile сохраняется осознанный horizontal scroll;
- состояние drag меняет cursor и блокирует accidental text selection.

## 5. Motion language

Motion не является декоративным слоем поверх готовой разметки. Он показывает появление,
изменение состояния или связь между элементами.

Используемые паттерны baseline:

- section reveal при входе в viewport;
- stagger для логотипов и элементов меню;
- fade/slide между табами;
- progress fill для активной use-case карточки;
- drag interaction roadmap;
- height animation FAQ;
- mobile menu panel + stagger items;
- shine CTA текста.

Базовые easing:

- layout/reveal: `--motion-ease: cubic-bezier(0.16, 1, 0.3, 1)`;
- controls: `--button-ease: cubic-bezier(0.4, 0, 0.2, 1)`;
- menu/control easing: `cubic-bezier(0.55, 0, 0.1, 1)`.

Ориентиры длительности:

- micro state: 180-267ms;
- panel/item reveal: 260-520ms;
- content transition: 500-700ms;
- long ambient background motion: 6-8s.

Каждый новый motion-сценарий должен описать:

1. что меняется;
2. какой элемент является источником движения;
3. начальное и конечное состояние;
4. timing/easing;
5. reduced-motion поведение.

## 6. Accessibility contract

- Секции используют семантический `section` и осмысленный heading hierarchy.
- Интерактивная control имеет accessible name.
- Меню имеет `aria-expanded`, `aria-controls`, `aria-hidden` и закрывается по Escape.
- Tab/accordion не зависят только от цвета.
- Клавиатурный фокус видим, кроме случаев, когда конкретный оригинальный control имеет
  собственный согласованный focus treatment.
- Декоративные изображения имеют пустой `alt`; content images - описательный `alt`.
- Ошибка формы связана с полем через `aria-describedby`.
- При смене состояния не теряется фокус и не создаётся ловушка для screen reader.

## 7. Архитектурные правила новых секций

Компонентная спираль:

```text
shadcn primitive
  -> brand primitive
    -> entity
      -> feature
        -> widget
          -> page
```

Пример для формы:

```text
Input / Textarea / Label / Button
  -> Field / FormMessage
    -> DemoRequestForm
      -> DemoRequestSection
        -> HomePage
```

Правила:

- данные карточек лежат рядом с widget в `sectionData.ts` или `sectionData.tsx`;
- props нетривиальных entities выносятся в `ComponentName.types.ts`;
- интерактивное состояние принадлежит feature, а не page;
- widget отвечает за композицию и порядок блоков;
- entities не знают индекс, номер колонки и окружение;
- CSS Modules отвечают за pixel-perfect layout, псевдоэлементы и keyframes;
- inline styles избегаются; динамические значения идут через `data-*`, class или custom
  property;
- новые primitives сначала проверяются на возможность переиспользовать существующий shadcn
  primitive.

## 8. Definition of done для новой секции

Секция считается готовой только если:

- имеет самостоятельную смысловую задачу и отличается по композиции от соседних блоков;
- использует baseline tokens и повторяемые primitives;
- имеет desktop, tablet и mobile layout;
- не создаёт горизонтального overflow страницы;
- все интерактивные состояния работают мышью, touch и клавиатурой;
- есть `hover`, `focus-visible`, `active/pressed`, `disabled` где они применимы;
- есть reduced-motion поведение;
- изображения имеют alt и не вызывают layout shift;
- нет console errors;
- проходит `yarn lint`, `yarn test --run` и `yarn build`;
- визуально проверена рядом с baseline на 375px и desktop.
